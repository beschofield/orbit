Pluto and Charon now keep each other company.

Your machine and Becca's each have a little terminal companion. They say hi when you open a terminal, pass notes between you, and show whether the other one is around.

Pluto and Charon are tidally locked: they always show each other the same face, and they circle a point in the space between them, about 19,600 km apart, once every 6.39 days. Charon was found in 1978, which is why Orbit listens on port 1978.

Open a terminal

That's it. Each new terminal starts with a greeting from your character. Any notes Becca left show up in Charon's bubble, marked with when she sent them. You'll also hear when she's read yours.

Commands

orbit note "lunch at 1?"
Send Becca a note. It pops up on charon at her next terminal. Up to 280 characters, emoji welcome.
orbit notes
See the last 20 notes from both of you.
orbit away "at the gym"
Mark yourself away, with an optional short message. It sticks until you come back.
orbit back
Go back to automatic presence: active, idle or away, based on when you last typed.
orbit status
Hide Becca's status from your prompt, or bring it back. orbit status on and orbit status off work too.
orbit hi
Say hi to Pluto.
orbit greet
Show the login greeting again.
orbit help
List every command, including ones you add later.
orbit doctor
Check that everything works. It explains what's wrong and how to fix it.

Your prompt

The start of your shell prompt shows how Becca is doing. It's read from a file, so it never slows your shell down.

☾ charon: active ☾ charon: away (lunch) ☾ charon: 💤 ✉ 2

💤 means charon is switched off or unreachable. ✉ counts notes you haven't seen yet; open a new terminal to read them.

The easy way: ask Claude

Orbit was built to grow, and every feature is a small capability. Open Claude Code in the repo on pluto and say something like:

Read CLAUDE.md, then use the new-capability skill to add a capability that counts down to our next trip and mentions it at login.

Claude will copy the template, write test cases first, build it, and check it against a fake Charon running on your own machine. Charon's real data is never touched.

What a capability is

A folder in capabilities/ with a small program in it. Orbit runs the program when something happens and hands it everything it needs as JSON. It answers with what the characters should say, events to remember (which sync to the other machine), and text for your prompt.

capabilities/countdown/
├── manifest.json   # its name, commands, and when it runs
├── main.py         # the program
├── README.md       # what it does
└── tests/          # example inputs and the output they should produce

It can run on a command (orbit countdown add …), at login, on a timer, or when an event arrives from Becca's machine.

By hand

  1. Copy the template: cp -r capabilities/example capabilities/countdown.
  2. Write a few test cases in tests/: an input and the output you expect.
  3. Fill in manifest.json: commands, triggers and the event types it records.
  4. Write main.py. It reads one JSON object and prints one JSON object.
  5. Check it: bin/orbit dev test countdown, then try it with bin/orbit dev run countdown login.
  6. Write its README.md.

Every rule lives in docs/capability-contract.md.

Sharing it with Becca

Code doesn't travel between the machines on its own; only notes and other events do. Commit and push your capability, and Becca runs git pull on charon. Orbit notices new capabilities within about 30 seconds, so nobody has to restart anything. orbit doctor tells you if one machine has something the other doesn't.
